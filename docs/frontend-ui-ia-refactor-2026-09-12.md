# Gyre WebUI 信息架构重构与视觉规范收敛（2026-09-12）

**范围**：`web/c5-ui/`（Agent·Console，React 18 + TS + Tailwind 3.4 + Vite，约 1 万行；构建产物写入仓库根 `web/`，由 `agent --serve` 经 rust-embed 内嵌）。
**问题陈述**（用户）：多个功能元素在页面不同位置重复出现且分布零散，布局混乱、信息层级模糊、定位功能成本高。
**方法**：先按「能力 → 全部入口 → 使用频率」做穷举盘点（含 file:line），再以「三条正交轴 + 单一事实源」重排信息架构（第一轮），随后把散落的字距/半径/表面/层级取值收敛成闭合令牌并做组件级清理（第二轮），最后用构建 + 真实浏览器（320 / 390 / 1024 / 1440 px，明暗双主题，7 强调色）验证。
**结论**：确认并修复 **7 类结构性重复**；删除 **2 个常驻重复入口、1 个重复确认框、1 个重复主行动、约 85 行自绘语言菜单**；新增 **1 个统一入口（⌘K 命令面板，9 条命令）**；设计令牌从 **7 种任意字号 / 12 种图标尺寸 / 6 档圆角 / 9 种半透明表面 / 5 处裸 z-index** 收敛为 **9 档字号 / 6 档图标 / 5 档圆角 / 3 级实体表面 / 9 档语义层（裸值 0）**；顺带修复 **强调色 × 主题的对比度缺陷**（14 组实测全部达到 WCAG AA）；功能零删除。

### 1.2 结构性问题（R1–R7）

- **R1 侧栏底部是杂物抽屉**。`Sidebar.tsx:150-251` 在 100px 内纵向堆叠了 5 类互不相关的语义：连接状态卡（只读）、2×4 图标格（导航 + 配置 + 破坏性混排）、主题开关、语言菜单、版本页脚。图标格把「文件浏览器（导航）」「设置（配置）」「清空（破坏性）」并排成等权重的四格，用户无法从视觉上判断哪个是安全操作。
- **R2 同一动作多入口多确认框**。清空对话在 3 处可达，且每处各自写了一个 `ConfirmDialog`（`Sidebar.tsx:253`、`AgentShell.tsx:174`、`SettingsPanel.tsx:299`），三份文案/标题/危险色靠人工同步。
- **R3 外观偏好双份实现**。主题与语言各有两套控件，且语言的自绘菜单与设置面板的原生 select 键盘路径、可达性语义完全不同。
- **R4 同时可见的重复主行动**。运行中时顶栏与输入框各有一个「停止」，两者样式、位置、点击后行为均等价。
- **R5 运行面板两个断点两套控件**。同一面板在 ≥xl 常驻、<xl 变抽屉，却由两个只差 `xl:hidden` 的按钮分别触发，且常驻态无法收起。
- **R6 三层遥测无层级**。顶栏胶囊、运行面板、统计面板都读同一批数字，但没有任何位置说明它们是「摘要 / 实时详情 / 历史聚合」的关系，读起来像三个互相竞争的数据源。
- **R7 同类控件两种外观**。模型、审批模式是「胶囊 + 下拉」（输入框**上方**），模式却是原生 `<select>`（输入框**内部底部**，紧挨发送按钮），三者同为会话级上下文开关。

## 二、信息架构重构

### 2.1 设计原则：三条正交轴，各自只有一个归属地

| 轴 | 内容 | 唯一归属地 |
|---|---|---|
| **会话生命周期** | 新建 / 清空 / 停止 | 顶栏 **⋮ 会话菜单**（+ ⌘K + 斜杠命令） |
| **视图切换** | 文件浏览器 / 统计 / 运行面板 | **侧栏导航**（+ 顶栏遥测按钮 + ⌘K） |
| **偏好设置** | 连接 / 外观 | **唯一的设置面板**（连接 · 外观两个标签页）（+ ⌘K） |

判定规则只有一句：**「换一段对话就不再需要」的进会话菜单；「换一段对话仍然需要」的进偏好。** 清空对话因此从设置面板移出（它是会话动作），主题/语言因此从侧栏移入设置面板（它们是偏好）。

### 2.3 单一事实源：动作注册表

新增 `src/components/agent/CommandPalette.tsx` 导出 `AppAction` 与 `AppAction[]`。`AgentShell` 只构造一次 `actions`（`useMemo`），由三方消费：

1. `CommandPalette`（⌘K，跨类目检索）
2. `Sidebar` 导航（按 id 白名单取 `files` / `stats`）与 `TopBar` ⋮ 菜单（按 `group === 'session'`）
3. 输入框斜杠命令（复用同一批 session 方法）

由此，「某功能在 A 处有、B 处没有」或「同一动作两套文案/图标」不再可能发生——R2/R3 是缺少这层抽象的直接后果。

## 三、设计规范 v2（Design Tokens）

### 3.1 收敛前后的量化对比

| 维度 | 重构前 | 重构后 | 收敛方式 |
|---|---|---|---|
| 字号 | Tailwind 6 档 **+ 7 种任意值** `text-[9.5px]…[15px]` | **9 档闭合** `2xs 11 · xs 12 · sm 13 · base 14 · md 15 · lg 17 · xl 20 · 2xl 24 · 3xl 30`（含行高） | 任意值全部消解进令牌，`text-[13px]`→`text-sm` 等 |
| 圆角 | `rounded-sm/md/lg/xl/2xl` 默认值与扩展值混用（2/6/8/14/20 + 扩展 20） | **5 档 + full**：`sm 4 · md 8 · lg 10 · xl 14 · 2xl 20` | 重定义 `md 6→8`、`lg 8→10`，语义固定为「小控件/控件/卡片/浮层」 |
| 阴影 | `soft / pop / glow` 三级但卡片无静置阴影 | **4 级**：`card`（静置卡片）→ `soft` → `pop`（浮层）→ `glow`（强调反馈） | 补 `card`，把「层级」变成可映射的选择 |
| 表面 | **9 种半透明叠加** `bg-surface-2/{40,50,60,70}` · `bg-surface-3/60` · `bg-surface/{60,70,80,95}` | **3 级实体表面**（`bg-surface` / `.card`＝`bg-surface-2` / `bg-surface-3`）+ 1 个玻璃长条类 `.glass-bar` | 见 §3.3 依据 |
| 图标 | **12 种尺寸** `10,11,12,13,14,15,16,17,18,20,22,26,30` | **6 档** `12 · 14 · 16 · 18 · 20 · 26` | 统一 stroke 1.8、当前色描边 |
| 区块标题 | 各处手写 `flex items-center gap-1.5 text-xs font-semibold uppercase tracking-wide text-muted` | 单一 `.section-label` / `<SectionLabel>` | 消除 6 处长尾漂移（`tracking-wide` vs `tracking-[0.16em]` vs `tracking-wider`），字距只剩 `0.08em` / `0.14em` 两个具名取值 |
| 键帽 | `Composer.KbdMini` + 面板内联拼写 | 单一 `<Kbd>` 原语 | 复用 |

| 浮层外壳 | Modal / 统计 Sheet / 命令面板各自重复 6 个类 | 单一 `.overlay-panel` | 任一处改动不再让弹窗「厚度」不一致 |

| 主题前景 | 硬编码 `text-white dark:text-[#06241f]` ×2 + `text-white` ×3 | 单一 `--c-on-primary` 令牌 → `text-primary-fg` | 见 §3.5 |

### 3.2 字体层级（闭合集）

```
2xs 11/15  微标签、页脚提示、bucket 分组名
xs  12/17  元信息、时间戳、次级说明
sm  13/19  行内正文、菜单项、表单标签
base14/21  输入框正文、Markdown 正文
md  15/23  顶栏标题、弹窗标题、侧栏 wordmark
lg  17/24  空态标题
xl  20/28  关键数字（累计 token）
2xl 24/32  统计页指标
3xl 30/36  欢迎页品牌字
```

**依据（审美）**：字号断层从 13 种压到 9 种后，相邻两级的比值稳定在 ≈1.15–1.2，视觉上形成「可预期的阶梯」；此前 `12/12.5/13/14` 四级挤在 2px 内，读者无法凭字号判断信息层级，只能靠颜色，导致整页看起来「平均用力」。

### 3.3 表面系统：为什么把半透明改成实体

新增 `index.css` 组件类：

```css
.glass-bar      { @apply border-border bg-surface/85 backdrop-blur-xl; }  /* 顶栏/侧栏/输入区/运行面板 */
.card           { @apply rounded-xl border border-border bg-surface-2; }
.card-inset     { @apply rounded-lg border border-border bg-surface-2; }
.overlay-surface{ @apply rounded-xl border border-border bg-surface shadow-pop; }
.overlay-panel  { @apply relative z-raised flex flex-col overflow-hidden border border-border bg-surface shadow-pop outline-none; }
.section-label  { @apply flex items-center gap-1.5 text-2xs font-semibold uppercase tracking-[0.08em] text-muted; }
.brand-sub      { @apply text-2xs uppercase tracking-[0.14em] text-muted; }
.chip           { @apply flex h-8 min-w-0 max-w-[220px] shrink-0 items-center gap-1.5 rounded-lg border border-border bg-surface-2 px-2.5 text-xs ...; }
.focus-ring     { @apply focus-visible:outline-none focus-visible:ring-2 focus-visible:ring-primary/60 focus-visible:ring-offset-2 focus-visible:ring-offset-bg; }
```

`.brand-sub` 是**唯一被具名豁免**的微标签：品牌副标题需要更松的字距与常规字重，与「面板内区块标题」语气不同。把它令牌化而不是留成 `tracking-[0.14em]` 任意值，是为了让字距维度仍只有两个具名取值。

**依据（审美 + 可读性）**：① 不同 alpha 会让同层级卡片看起来处于不同高度，视觉重心散乱；② 背景是随视口变化的极光渐变，半透明表面的**实际对比度不可预测**，浅色主题下 `/40` 会糊成灰块；③ 实体令牌让「面板 / 卡片 / 控件」三层对比度恒定，是「简洁、专业」观感的地基。玻璃拟态只保留给 4 个跨视口长条容器——那里它承担「内容在其下方滚动」的语义，而不是装饰。

### 3.4 间距节奏

- 面板内边距：`1rem`（抽屉/运行面板）、`1.25rem`（弹窗主体，新增 `spacing.panel`）
- 区块间距：`space-y-5`（1.25rem），新增 `spacing.section = 1.5rem` 供大区块
- 控件高度：`sm 32 / md 40 / lg 44`；工具栏行高：顶栏 `h-14`、侧栏品牌行 `h-14`
- **视觉重心锚点**：侧栏品牌行从 `h-16` 改为 `h-14`，与顶栏对齐 → 外壳上沿只剩一条水平基准线，消除重构前「左侧比右侧高出 8px」的错位。

### 3.5 色彩：强调色 × 主题的对比度闭环

盘点时发现 `applyAccent`（`SettingsPanel.tsx`）存在一个**真实缺陷**，它同时违反「色彩搭配」与可访问性：

1. 它用**行内样式**把同一组值写进 `--c-primary`，行内样式优先于 `.dark` 规则 → 暗色主题的主色被浅色主题的深色值覆盖（连默认 Teal 也一样）；
2. 前景色 `text-white dark:text-[#06241f]` 是硬编码的，与强调色无关 → 选 Rose / Indigo / Violet 这类深色 accent 时，暗色主题下出现「深底 + 深墨字」。

**修法（三层）**：

| 层 | 改动 |
|---|---|
| 值域 | accent 表只描述浅色主题取值；暗色主题由 `resolveAccent()` 现场向白混合派生（primary +32%，glow +16%），避免深色 accent 大面积铺在深底上变成低对比色块 |
| 选色 | 新增 `--c-on-primary` 令牌 + `text-primary-fg`；由 `bestForeground()` 在「白」与「深墨 `6 36 31`」之间**按对比度择优**，而不是按主题硬编码 |
| 一致性 | 一是色板预览的小圆点走同一条 `resolveAccent()`（暗色下预览不再显示未提亮的原色）；二是 `useEffect` 依赖 `theme` 重新派生色阶（否则「先选 accent 再切主题」会残留浅色值）；三是 `index.css` 的首帧兜底值同步为 `applyAccent('Teal')` 的结果，消除首帧闪色 |

同时按对比度筛选色板，下调两个不达标取值：

| accent | 原值 | 白字对比度 | 新值 | 结果 |
|---|---|---|---|---|
| Teal（浅色） | `13 148 136` | 3.8:1（深墨也只有 4.4:1，两侧都不达标） | `15 118 110` | 白字 **5.47:1** |
| Emerald（浅色） | `5 150 105` | 3.8:1 | `4 120 87` | 白字 **5.48:1** |

**实测（浏览器内读取 `getComputedStyle` 计算 WCAG 对比度，7 accent × 2 主题 = 14 组）**：全部 ≥ 4.5:1，失败 0；暗色下 7 组都由 `bestForeground` 选中深墨字（5.0–7.6:1），浅色下 6 组选中白字（4.7–6.3:1）、Amber 选中深墨（5.15:1）。

## 八、权衡、刻意的取舍与后续

### 8.1 代价：主题/语言从「1 击」变「2 击」

去重不是免费的：删掉侧栏常驻开关后，主题从 **1 击** 变成 **2 击**（设置 → 外观 → 选）或 **1 次快捷键**（`Ctrl⇧L`）；语言从 1 击 + 菜单选择变成 2 击 + 一次选择。

**为什么接受**：① 这两项是「设一次」的偏好，不是核心任务，用户陈述的痛点是「重复与分散」而非「主题难找」；② `Ctrl⇧L` 补回了不劣于原来的路径（且不需要移动鼠标）；③ 保留了唯一一套控件，语言的两套键盘路径（自绘菜单 vs 原生 select）差异被消除。**如果后续观察到主题切换频率确实高**，正确做法不是把按钮加回侧栏，而是把 `action.theme` 提到命令面板首位或再加一个直绑快捷键。

### 8.2 刻意保留的「非重复」

- **模型**：工具栏可切换 + 运行面板只读清单。前者是控件、后者是数据（含 `id`、默认标记），属「摘要/详情」关系。
- **连接**：侧栏一行紧凑状态（含主机名，可点入设置） + 运行面板详情（含重连按钮） + 设置表单（可编辑）。三者职责分别为「一眼可见 / 运行期处置 / 编辑」。
- **遥测**：顶栏总量摘要（且是面板开关） + 运行面板实时详情 + 统计面板历史聚合。粒度和时间范围不同，已在面板内以 Section 标题明示。
- **错误横幅**：唯一承载「当前连接已失败」这一瞬时态，不可合并。
